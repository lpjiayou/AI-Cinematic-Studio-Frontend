## Current structural baseline

### Global workspace

- A wide top header combines product identity, six global destinations, environment/status copy and user controls.
- Home, AI Director and Projects are actionable. Assets, Create and Works are visible but disabled.
- The top navigation is coherent at desktop width but consumes meaningful vertical space and does not provide a compact project-first hierarchy for production work.

### Project workspace

- A second navigation row exposes Overview, Planning, Content, Production, Post and Delivery.
- Overview is disabled. Planning adds a third navigation layer; project AI Director, Series Planning and Continuity are disabled.
- Story World, Character Studio and Script Studio are the most complete authored workspaces. Their visual language is reusable, but their page-local component density makes cross-workspace behavior inconsistent.

### Production / post / delivery

- Production uses a left run navigator, dense center work area and right state/next-action/truth-boundary inspector.
- The screen exposes implementation-facing identifiers and machine states such as `REAL_VIDEO_PLAN_READY`, run/job refs and `CPU · LOCAL_EVIDENCE` as primary reading material. These are useful for evidence but not a user-centered production vocabulary.
- The current page can read legacy G4/G5 history and demonstrate fail-closed behavior. It cannot reach the four method-aware successor resources and must not be presented as the complete production path.
- Post and Delivery correctly preserve QC failure and “not created” outcomes. This is a strong truth boundary to retain.

### Responsive and keyboard posture

- Script Studio demonstrates a viable mobile pattern: one primary canvas plus navigator/inspector drawers and an explicit unsaved-work guard.
- The generic Production control plane has no equivalent captured 390 px evidence in this audit. Static structure suggests substantial compression risk from nested navigation, the run rail and the inspector.
- Existing semantic buttons, focus treatment and modal/drawer patterns are reusable. Full keyboard traversal and focus order were not re-executed because the cloud browser could not navigate the local origin.
